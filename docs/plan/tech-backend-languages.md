# Technology selection: back-end language (Go, Rust, C++)

**Status:** Draft · **Owner:** TeddyBertrand (the team confirms) · **Decision:** none. Evidence for a discussion, not a proposal: no ADR is opened, no rule is changed and [ADR 0001](../adr/0001-backend-fastify.md) stays as it is.

The repository rule is TypeScript only, and [`tech-backend.md`](tech-backend.md#language) says comparing languages would be a new ADR. A team member asked what Go, Rust and C++ would give. If the team opens that ADR, this is where to start. The runs, fixes and load figures are in [`spikes/backend-languages/runs.md`](spikes/backend-languages/runs.md).

## What was compared

Three candidates, one per language, on the six probes and the load method of the TypeScript spikes, with Fastify 5.12.8 rerun as the reference: **Go with Huma** (OpenAPI from the handler types), **Rust with Axum and utoipa** (OpenAPI from annotations), **C++ with Drogon** (no OpenAPI generation, so the description is written by hand). All three passed all six probes, and a deliberate break of one rule per probe failed a test every time.

| Measure                                                        | Fastify           | Go + Huma            | Rust + Axum        | C++ + Drogon                          |
| -------------------------------------------------------------- | ----------------- | -------------------- | ------------------ | ------------------------------------- |
| `/ping` and save-time check, requests per second (median of 3) | 42,314 and 24,663 | 78,362 and 51,585    | 89,388 and 103,123 | 92,141 and 48,380                     |
| Idle memory                                                    | 89.7 MB           | 12.4 MB              | 9.0 MB             | 11.6 MB                               |
| Manual fixes during the probes                                 | 8                 | 7                    | 3                  | 0 (but 2 libraries built from source) |
| Advisories on its own packages: all time, last 24 months       | 19, n/a           | 0 (`huma`, `jwx/v3`) | 16, 4              | 8, 3 (NVD)                            |
| Token with no `exp` claim accepted                             | not tested        | yes, until fixed     | no                 | yes, until fixed                      |
| A hung call in the hook                                        | hand-written      | abandoned, leaks     | cancelled          | abandoned, leaks                      |

**How fragile it is.** Across all 19,683 integer weightings from 1 to 3, Go leads in 92.5%, Rust in 2.1%, Fastify in 0.3%, and 5.2% tie. The ranking turns on one row: with the other weights unchanged, Fastify overtakes Go only when the language-fit row weighs 6 or more, twice its proposed 3. Taking a point off Go, Rust and C++ on security and learning curve gives Go 79, Fastify 77, Rust 74; leaving Fastify's speed at 5 gives Fastify 81, Go 85. C++ is last under every weighting. So the question is not "which language is best" but "how much is one language across the repository worth".

## Read this before using the table

- **It recommends nothing.** A second language means a second toolchain in CI and in the hooks (all TypeScript today), a change to the repository rule, and an ADR the team accepts. None of that is costed.
- **The scores are one person's.** I wrote the three spikes in one session, after reading the TypeScript results, with no stopwatch, so fix counts are lower bounds. The learning curve is scored from what the spikes needed, **not from the team's experience, which nobody has measured**. Each member should score the matrix alone, as the [bootstrap](../subject/BOOTSTRAP.md#weighted-decision-matrix) asks.
- **The load generator limits the three fast servers**, so their order among themselves means nothing; the gap to Fastify is real. On trivial routes it says little about a workload dominated by the database and third-party calls.
- **The Go standard library is left out of the advisory count**, as Node's runtime was for Fastify. Counted, it has 182 advisories, 77 in the last 24 months, fixed by a toolchain upgrade. The C++ advisory data is the thinnest (the NVD only; OSV has none).
- **Worth checking in the TypeScript guards, whatever the language:** two of the three JWT libraries here accept a token with no expiry by default, and the TypeScript spikes never tested that case.
- The spike code stays in local repositories (`~/projects/spikes-area/`), not pushed, like the TypeScript spikes.
